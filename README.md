# Mobee Cars — Technical Assessment

Tinder-style car browsing app with offline support, built for the Mobee Cars mobile developer assessment.

- **Mobile** — React Native + Expo + SQLite (offline-first)
- **Backend** — Laravel 11 + Sanctum
- **Admin** — Laravel Blade + Tailwind

---

## Setup (5 minutes)

### Backend

```bash
cd backend
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate --seed
php artisan serve
```

API now running at `http://127.0.0.1:8000/api`. Visit `http://127.0.0.1:8000/admin/login` for the admin dashboard.

### Mobile app

```bash
cd mobile
npm install
cp .env.example .env
npm start
```

Then press `i` for iOS Simulator, `a` for Android Emulator, or scan the QR code with the Expo Go app on a physical phone.

> **Physical phone?** Two extra steps:
> 1. In `backend/`, start with `composer serve:lan` (binds to `0.0.0.0` so the phone can reach it)
> 2. In `mobile/.env`, change `localhost` to your machine's LAN IP — e.g. `http://192.168.1.10:8000/api`

## What it does

**Mobile** — 4 tabs: **Discover** (Tinder-style swipe deck) · **History** (all swipes) · **Insights** (most-liked brand / model / type with charts) · **Profile** (account, settings, sync, sign out).

Works fully offline — every swipe writes to local SQLite immediately. Queued swipes flush to the server on reconnect, foreground, and manual sync.

**Admin** — 3 sections: **Overview** (system-wide stats) · **Users** (all users + per-user activity & reports) · **Cars** (full CRUD on the 30-car inventory, image upload or URL).

**API** — `POST /api/auth/{register,login,logout}` · `GET /api/auth/me` · `GET /api/cars` · `POST /api/likes/sync` · `GET /api/likes` · `GET /api/reports/me` — all bearer-token protected.

## Architecture

```
+--------------------------------------------------------------+
|  MOBILE  (React Native + Expo)                               |
|--------------------------------------------------------------|
|  Zustand auth + sync stores                                  |
|  axios + bearer token                                        |
|                                                              |
|  expo-sqlite   cars table   (local inventory)                |
|                user_car_likes (queued swipes)                |
|                                                              |
|  NetInfo + AppState  -->  auto-sync on reconnect / foreground|
+--------------------------------------------------------------+
                          ^
                          |  HTTPS / JSON
                          v
+--------------------------------------------------------------+
|  BACKEND  (Laravel 11 + Sanctum)                             |
|--------------------------------------------------------------|
|  /api/*    Bearer-token API   -->  mobile app                |
|  /admin/*  Session web auth   -->  Blade dashboard           |
|                                                              |
|  SQLite (dev) - cars, users, user_car_likes                  |
+--------------------------------------------------------------+
```

**Offline-first** — every swipe writes to local SQLite first. The UI never blocks on the network. Queued swipes flush in the background. On login, the server's authoritative swipe history is restored to local SQLite so the same user sees the same state on every device.

## Tech notes

- **Sanctum** runs as token guard for the mobile API and session guard for the admin dashboard.
- **SQLite** is the dev database. Production would swap in MySQL/Postgres via `DB_CONNECTION` — no schema changes needed.
- **Image uploads** in admin save to `storage/app/public/cars/` (symlinked via `php artisan storage:link`). The mobile API resolves relative paths to absolute using the current request host, so the same image URL works for desktop admin and LAN-connected mobile clients.
- **Car photos** are sourced from Wikipedia Commons — real model photos, not stock placeholders.
